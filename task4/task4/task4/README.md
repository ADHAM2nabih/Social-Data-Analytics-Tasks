# Task 4: Evaluation, Error Analysis, and Deployment

This document outlines the complete programmatic implementation of Task 4. The goal of this task was to formally evaluate the models generated in Task 3, conduct a deep-dive error analysis on their failures, and successfully deploy the winning model to a production-ready Web API and Frontend interface.

---

## 1. Model Selection & Optimization (`best_model_selection.py`)

This script acts as the automated adjudicator to find the best configuration among all previously processed datasets and algorithms.

### **Methods Used:**

- **Feature Extraction:** Bag-of-Words (`CountVectorizer` with top 2,500 features).
- **Dimensionality Reduction:** Principal Component Analysis (`PCA`) (utilized specifically to optimize `GaussianNB` compatibility).
- **Classification Algorithms:** `MultinomialNB`, `GaussianNB`, and `DecisionTreeClassifier`.
- **Validation Strategy:** 80/20 Train-Test split with `stratify=y` to ensure class distribution remains balanced.
- **Persistence:** `joblib` to serialize and save the trained Python objects.

### **What this section does:**

1. Loads the labeled dataset from Task 3 containing three textual preprocessing schemes (`v1_basic`, `v2_no_stop`, `v3_stem`).
2. Iterates through every combination of Scheme + Algorithm and trains them simultaneously on the data.
3. Tests their accuracy using the 20% holdout set.
4. Generates a terminal leaderboard and automatically selects the highest-scoring combination (e.g., `Multinomial Naive Bayes` on `v1_basic`).
5. Dumps the winning Model, Vectorizer, and LabelEncoder into `.pkl` binaries inside the `models/` directory for the backend to use.

---

## 2. Error Analysis (`error_analysis.py`)

This script fulfills the requirement to analyze _where_ and _why_ the algorithms fail.

### **Methods Used:**

- **Evaluation Metrics:** `confusion_matrix` from scikit-learn.
- **Data Visualization:** `matplotlib` and `seaborn` (Heatmaps).
- **Data Wrangling:** `pandas` to align the original text with test indices.

### **What this section does:**

1. Loads the winning `.pkl` models generated by the previous script.
2. Vectorizes the data and re-runs predictions strictly on the Test Set.
3. Calculates a raw **Confusion Matrix** mapping (`Negative`, `Neutral`, `Positive`) and plots it using `seaborn.heatmap`. The graph is saved to `docs/confusion_matrix.png` to be included in the final report.
4. Scans the test outputs for False Positives and False Negatives (cases where `True_Label != Predicted_Label`).
5. Extracts the raw uncleaned text, the true label, and the predicted label, saving them to `docs/model_errors.csv` so the qualitative (manual reading) portion of the error analysis can be easily completed.

---

## 3. Backend Deployment (`api.py`)

This script fulfills the deployment requirement by acting as a microservice simulating a real-world software architecture.

### **Methods Used:**

- **Web Framework:** `Flask`, `request`, `jsonify`.
- **Natural Language Processing:** `NLTK` (`word_tokenize`, `WordNetLemmatizer`, `stopwords`), Regular Expressions (`re`).

### **What this section does:**

1. Instantiates a live `localhost` HTTP web server listening on port `5000`.
2. Upon startup, it securely loads the `.pkl` files (Model, Vectorizer, LabelEncoder) generated by the selection algorithm into server memory.
3. Exposes a `POST /predict` endpoint.
4. When a string is received, it pushes it through the exact same NLP pipeline used during training (lowercasing, regex cleanup, tokenization, stopword removal, and lemmatization).
5. Vectorizes the cleaned input computationally, predicts the sentiment array, extracts the confidence score utilizing `.predict_proba()`, and returns a highly structured JSON response to the client.

---

## 4. Frontend Interface (`frontend.py`)

This script serves as the consumer-facing user interface to interact with the backend model without requiring code.

### **Methods Used:**

- **UI Framework:** `Streamlit`.
- **HTTP Calling:** `requests.post`.

### **What this section does:**

1. Generates a clean, interactive Web Dashboard.
2. Accepts textual input (e.g., a Reddit comment or title) from the user through a text area.
3. Safely packages the input into a JSON payload and makes an HTTP POST request to the Flask API (`api.py`).
4. Receives the algorithmic prediction and dynamically updates the UI to reflect the Sentiment (Green for Positive, Red for Negative) alongside the model's numerical confidence level.
5. Displays the raw JSON developer packet to prove the API integration was successful.
